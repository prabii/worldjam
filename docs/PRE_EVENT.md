## Still to do, in priority order

### 1. Run the latency spike on the real phone — go/no-go

Nothing else matters until this passes. Build a dev build, open the app, read
the latency badge.

```bash
npx expo run:android --device
```

**Green (<50 ms total)** → proceed.
**Amber/red** → do not build features. Fix this first. Things to try, in order:

- Confirm the badge says the stream is `Exclusive`, not `Shared` (check logcat:
  `adb logcat -s WorldJamEngine`).
- Confirm sample rate matches the device's native rate — a mismatch forces
  resampling and adds latency. The log line prints both.
- Try `setBufferSizeInFrames(burst * 1)` instead of `* 2` in
  `openPlaybackStream`. Lower latency, higher glitch risk.
- Disable any system audio effects / Dolby processing in device settings.

### 2. Choose and wire the Gemma backend

See [`src/ai/runtimes/mediapipeRuntime.ts`](../src/ai/runtimes/mediapipeRuntime.ts).
The contract is one `generate(prompt) → string` function; everything else is
built and tested. Measure `elapsedMs` on device — if it regularly exceeds 4 s,
either shrink the model or accept the rule-based arranger (which is genuinely
good and always available).

**This is not on the critical path.** The app is fully demoable without it.

### 3. ARCore capability check

Look up the exact loaner handset on Google's ARCore supported-devices list.
Per HLD §2, AR is Tier 3 and **removable** — the decision is simply in or out,
and out is a perfectly good answer.

### 4. Prepare the dev build before travelling

The dev build is the native shell. Building it at the venue on conference wifi
is a bad plan — the Gradle dependency download alone is gigabytes.

```bash
npx expo prebuild --platform android
npx expo run:android --variant debug
```

Then during the event, JS changes hot-reload without rebuilding.

### Build gotchas found the hard way

`android/` is regenerated by `expo prebuild`, so **every one of these must be
re-applied after a prebuild** or the build breaks again. They live in
`android/gradle.properties`.

**1. Memory.** This machine has 7.4 GB RAM. Gradle's default 2 GB daemon heap
OOM-crashed the JVM outright. Worse, the CMake/prefab step **forks another
JVM**, so a heap that fits on its own still dies at prefab time with *"The
paging file is too small for this operation to complete."* Settings that work:

```properties
org.gradle.jvmargs=-Xmx900m -XX:MaxMetaspaceSize=320m -Dfile.encoding=UTF-8
org.gradle.parallel=false
kotlin.compiler.execution.strategy=in-process
reactNativeArchitectures=arm64-v8a
```

Close browsers and other editors before building. Do not run `npm test` and a
Gradle build at the same time - Node will fail to spawn workers.

**2. Kotlin version.** Expo's bundled Compose Compiler 1.5.15 requires exactly
Kotlin 1.9.25, but 1.9.24 gets resolved and `expo-modules-core` fails to
compile. Fix: `android.kotlinVersion=1.9.25`.

**3. `local.properties` escaping.** Java properties files treat backslash as an
escape character. A Windows SDK path must be written with the colon and every
separator escaped (`C\:\Users\...`), not raw. Otherwise Gradle reports *"The
filename, directory name, or volume label syntax is incorrect"* - which sounds
like a missing SDK but is not.
